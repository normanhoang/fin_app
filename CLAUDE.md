# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

fin_app is a SwiftUI + SwiftData iOS personal-finance app that syncs bank data via SimpleFin.
Toolchain: Xcode 26.5 / iOS 26 SDK / Swift 6, iOS deployment target 17.0.

## Build & Test

The Xcode project is **generated by xcodegen** from `project.yml` (the source of truth).
`FinApp.xcodeproj` is regenerated, not hand-edited.

- After **adding/removing** source files: `xcodegen generate` (xcodegen snapshots the file
  list; new files are not picked up otherwise). Editing existing files needs no regenerate.
- Build: `xcodebuild build -scheme FinApp -destination 'platform=iOS Simulator,name=iPhone 17'`
- Test (all): `xcodebuild test -scheme FinApp -destination 'platform=iOS Simulator,name=iPhone 17'`
- Single unit test: append `-only-testing:FinAppTests/AnalyticsTests/testDetectsMonthlySubscription`
- UI tests only: `-only-testing:FinAppUITests`
- Targets: `FinApp` (app), `FinAppTests` (unit), `FinAppUITests` (XCUITest).

Gotcha: the model type `Category` is ambiguous in the **test** target — qualify it as
`FinApp.Category` (e.g. `FetchDescriptor<FinApp.Category>()`). App-target code uses `Category` bare.

Gotcha: never put a `LazyVGrid` inside a `List` row — crashes at launch with recursive
`-[UICollectionView _updateVisibleCellsNow:]` (List is collection-view-backed). Use a
non-lazy `Grid` (see the Recurring calendar card).

### DEBUG launch environment variables
Set via `SIMCTL_CHILD_<VAR>` for `simctl launch`, or `XCUIApplication.launchEnvironment`:
- `FINAPP_SAMPLE=1` — inject `SampleData` into the on-disk store.
- `FINAPP_TAB=<0–5>` — initial tab.
- `FINAPP_UITEST=1` — use an **in-memory** container + fresh sample data each launch
  (clean, deterministic; used by `FinAppUITests`).

### Archive & export IPA (App Store)
Bump `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` in `project.yml`, then `xcodegen generate`.
- Archive: `xcodebuild archive -scheme FinApp -destination 'generic/platform=iOS' -archivePath build/FinApp.xcarchive -allowProvisioningUpdates`
- Export: `xcodebuild -exportArchive -archivePath build/FinApp.xcarchive -exportPath build/export -exportOptionsPlist exportOptions.plist -allowProvisioningUpdates`
  → `build/export/FinApp.ipa` (method `app-store-connect`, automatic signing).
- Gotcha: the export **auto-bumps `CFBundleVersion`** (App Store Connect exports manage the
  build number by default), so the IPA's build number can differ from `project.yml`.
- App Store assets (listing copy, privacy policy, support page, screenshots) live in `AppStore/`.
- Screenshots: iPhone 11 Pro Max sim (1242×2688, 6.5" spec). Per tab:
  `SIMCTL_CHILD_FINAPP_SAMPLE=1 SIMCTL_CHILD_FINAPP_TAB=<n> xcrun simctl launch ...`, appearance
  via `xcrun simctl ui <id> appearance dark|light`, capture via `xcrun simctl io <id> screenshot`.

### Deploy to a physical device
Build with `-destination 'platform=iOS,id=<UDID>' -allowProvisioningUpdates`
(signs as "Apple Development"), then
`xcrun devicectl device install app --device <device-id> <FinApp.app>` and
`xcrun devicectl device process launch --device <device-id> com.normanhoang.finapp`.
The phone must be **unlocked** for launch to succeed.

## Architecture

**Entry / navigation.** `FinAppApp` builds the `ModelContainer` and owns `SyncCoordinator` +
`AppLock`, then shows `RootView`. `RootView` is a horizontal **paging ScrollView** (all five
pages built up-front) with a **custom bottom bar**. It deliberately does **not** use
`.tabViewStyle(.page)` — page-swiping between the per-tab `NavigationStack`s triggered a
`UINavigationBar` layout assertion (SIGABRT). `AppRouter` (`@Observable`, in the environment)
holds `selectedTab` and `txnFilter`; Dashboard tiles call `router.showTransactions(_:)`,
which sets `txnFilter` then `selectedTab = AppTab.transactions.rawValue` to deep-link into a
pre-filtered Transactions list. Page order: Accounts · Transactions · Dashboard · Recurring ·
Settings (Dashboard centre + default); the `AppTab` rawValue == physical pager position ==
tab-bar item index == the `launch(tab:)` indices in `FinAppUITests.swift`, so all **four**
must move together when reordering. The pager builds every page up-front, so XCUITest
`exists` is true for elements on off-screen pages — a wrong tab index hangs
`while !isHittable` loops instead of failing (the `launch` helper asserts the landing
nav bar to catch this).

**SwiftData layer.** `Models/AppSchema.swift` lists every `@Model` type in one place —
**update `AppSchema.models` when adding a model.** Migrations are lightweight only: a new
stored property MUST be optional or have a default (e.g. `var isManual: Bool = false`) or the
on-disk store fails to open. `makeInMemoryContainer()` is used by tests/previews. The container
must stay retained (held by `FinAppApp`); a dropped container makes `@Query` trap.

**Sync pipeline** (`SimpleFin/`): `SyncCoordinator` (UI-facing `@Observable`, `@MainActor`;
loads the access URL from `CredentialStore`/Keychain; gated by `SyncThrottle`) →
`SimpleFinClient` (networking; TLS pinning via `CertificatePinner`; HTTP basic-auth from the
access URL) → decodes `SimpleFinDTO` → `SyncService.sync` upserts into SwiftData **keyed by
SimpleFin id**, so re-syncing is idempotent. Manual accounts use `"manual-<uuid>"` ids that
never collide, so sync leaves them untouched. After persisting, the coordinator runs
`CategorizationEngine.categorizeAll`, `RecurringDetector.refresh`, and records a
`NetWorthSnapshot`.

**Analytics** (`Analytics/Analytics.swift`): pure static functions over `[Account]`/`[Transaction]`
(`netWorth`, `monthlyIncome/Spending`, `spendingByCategory`, `monthlyTrend`) — no UI coupling,
unit-tested. Net-worth history comes from `NetWorthSnapshot` (one row/day, recorded on sync;
no backfill).

**Categorization** (`Categorization/`): `CategorySeed.seedIfNeeded` seeds default categories +
keyword `CategoryRule`s on first run; `ensureMissing` idempotently adds newly-shipped defaults
to existing stores. `CategorizationEngine` applies keyword rules; `learn()` sets a manual
category and records a high-priority user rule. `Transaction.categorizedByUser` protects manual
choices from being overwritten on re-sync.

**Recurring** (`Recurring/RecurringDetector.swift`, `Features/Recurring/`): groups outflows by
normalized merchant, infers a cadence, and `refresh()` reconciles detections into `RecurringBill`
rows. Bills carry `confirmed` and `dismissed` flags; **dismiss sets `dismissed = true` (not
delete)** so re-detection doesn't resurface a dismissed candidate.
`RecurringSchedule.occurrences` projects future due dates for the calendar view with
calendar-aware steps (monthly = `+1 month`, not `Cadence.days`); Calendar month intervals
are **end-exclusive**. View mode persists via `@AppStorage("recurringShowCalendar")`.

### Conventions
- **Amount sign**: negative = outflow/debit, positive = inflow (SimpleFin). Debt account
  balances are stored negative.
- **User-rename override**: `Account.displayName = customName ?? name`; sync only writes the
  bank-provided `name`, so a user rename in `customName` survives re-syncs. Same idea applies
  whenever sync would clobber a user edit.
- **UI testing**: drive via accessibility identifiers (`netWorthCard`, `tab-<Title>`,
  `txnRow-<id>`, `accountRow-<id>`, `accountNameField`, `categoryMenu`, `category-<Name>`,
  `txnSearchField`). XCUITest fires List `NavigationLink`/`Menu` rows reliably; synthetic
  cursor clicks do not. Edge back-swipe works via
  `coordinate(...).press(forDuration:thenDragTo:)`. Lazy List rows scrolled off-screen are
  **absent from the element tree** (`exists == false`) — assert navigation landings on
  `app.navigationBars["Title"]`, not on off-screen fields. `xcodebuild test` runs on a
  **cloned** simulator, so `simctl io <id> screenshot` can't capture test UI; dump
  `app.debugDescription` from inside the test instead.
- Money/color formatting lives in `Support/Formatting.swift` (`Money.string`, `Color(hex:)`).
  Biometric gate in `Support/AppLock.swift`.
